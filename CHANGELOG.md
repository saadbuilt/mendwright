# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and version numbers follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
While the version starts with 0, a minor release can change the public API.

## [Unreleased]

- `mendwright notify` posts a short summary of one run to a webhook (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#alerts)): how many selectors were repaired, from fingerprints, by the model, or found inside an iframe or a shadow root, and how many were confirmed, the cookie banners, popups and interruptions handled, and what needs a human, in mendwright's own words, such as `` `pay` is marked destructive, so mendwright did not repair it ``. `--format slack` (the default) works with Slack incoming webhooks and the services that take their format; `--format json` sends a JSON document of at most 16 KiB. It sends counts, codes, mendwright's phrases, key names (none with `--detail counts`), the title, the run and pull request links and how the tests ended: never page HTML, input values, selectors, the model's reasoning, reasons, popup text, page paths, test names or provider and model names. The URL comes only from `MENDWRIGHT_WEBHOOK_URL`, must be `https://` (`http://` only on localhost), is never printed and no redirect is followed. Of the webhook's error answer, only one word such as Slack's `no_service` that is no part of the URL is shown, and the URL, its path, its query and each path segment and query value of 8 characters or more are written as `***` in any form. Messages name the webhook by its scheme and host, with a label of the host that looks random, such as the id of an AWS Lambda function URL, as `***`. `--when changes|attention|always` says when to send, `--run`, `--since` and `--all` which events are the run, and `--dry-run` prints the payload. It tries once more on HTTP 429, a 5xx and network errors, cuts each attempt off after `--timeout` seconds, however slowly the webhook answers, and a webhook that fails exits 0 unless `--fail-on-error`.
- Every journal event has `run`, the id of the run that wrote it: `MENDWRIGHT_RUN_ID`, or on GitHub Actions `gh-<run id>.<attempt>`. A `MENDWRIGHT_RUN_ID` that is not 1 to 100 letters, digits, `.`, `_`, `:`, `/` or `-` is ignored, with one WARNING from `mendwright.open()`, and does not fail the tests. `Journal(run=...)` sets or turns off the id. `mendwright doctor` shows the run id and where it comes from, and lists an invalid one under Problems.
- The journal has a `heal.declined` event for each heal that was not tried or did not apply, with a `code` (`destructive`, `page_guard`, `disabled`, `no_provider`, `role_unknown`, `guard`, `rate_limit`, `not_here`, `no_proposal`, `gate`, `dry_run`, `list_empty`, `list_not_found`, `list_waits_fix`, `get_by`, `frame`, `shadow` or `other`) and the `reason` the error gives, and a `flow.stop` event right before mendwright stops a flow that cannot go on (`interruption_loop`, `popup_loop`, `step_cap`, `step_again`, `step_moved`, `no_step`), with no message text. A `heal.quarantine` of a heal saved in an earlier run, of a key marked destructive since, has `by` `destructive`, so `mendwright notify` says the key is marked destructive, not that the repair was wrong.
- The GitHub Action sends the alert with the inputs `webhook-url` (pass a secret), `webhook-format`, `notify-when`, `notify-detail` and `journal-run`, and the output `notified`. The step runs after the pull request, for runs on `push`, `schedule`, `workflow_dispatch` and `workflow_run` the action let through, never on `pull_request`; only it gets the URL, which it masks with the parts `mendwright notify` masks before it prints anything, and it never fails the job. The job summary gets a "This run" section with the alert's text.
- Open shadow roots, at any depth, on Playwright (sync and async) and Selenium (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#shadow-dom)). Each time a key's selector matches, the fingerprint read also reads the shadow hosts around its element and saves them as the key's `shadowHosts`, each as a CSS selector that matches it and nothing else where it sits: its tag with a test id, id or name, such as `my-app[id="root"]`, or a custom element's tag alone when it is the only one there, else `null`. A key whose element was last found inside a shadow root heals only inside it: the fingerprint tier and the model get that shadow root's HTML and nothing from the page around it, the XPath they find is checked there and turned into a CSS selector for the same element, and that CSS must pass the live check inside the shadow root (one visible element of the key's role). It is saved as the Playwright chain of the hosts and the CSS, `my-app[id="root"] >> [data-testid="save"]`, with the hosts as the candidate's `shadowHosts`, and looked up strictly: each host must match one element where it sits and have an open shadow root, and only a match inside that shadow root counts, never one in the host's light DOM, a shadow root inside it, or another host with the same tag. When the shadow root can't be entered (the host is gone, there are two, or it is closed now), when a host can't be told apart, when the element has no CSS form, or when the shadow root is inside an iframe, the heal is refused with the reason, and never run on the page. When none of a key's selectors matches on the page and one matches one element inside exactly one open shadow root, it is looked up there from now on, with no model call: a CSS selector as it is, an XPath through a CSS form of its element; that counts as a heal with source `shadow`. It is refused, with the reason and no model asked, in dry run, under `MENDWRIGHT_DISABLE=1`, while a `guard=` blocks heals, for a key marked destructive, for a lookup quarantined before, on a page the key was never found on, when the selector matches in several shadow roots or several elements there, when a host can't be told apart, for an XPath whose element has no CSS form, and when the live check fails. So Selenium finds an element inside a shadow root from `heal.locator()` and `heal.driver.find_element(By.CSS_SELECTOR, ...)`. Quarantines count in their own place. `mendwright fix` writes such a heal as its chain only where the old selector is passed to a Playwright page or locator method in a Python file, and lists every other place (`shadow_call`) and the key of a `heal.driver.find_element()` call with `By.CSS_SELECTOR`, `By.ID` or `By.NAME` (`shadow_driver`). `mendwright check` and `heal.drift()` decide as a run does (`would heal` with detail `shadow`), and `mendwright report` shows the shadow root of each selector. With `nonempty=True`, a list that was inside a shadow root is never looked for: the list fingerprint says `"shadow": true`. Closed shadow roots are out of reach. With the fingerprint tier off nothing is read after a match, so a key's element is not known to be inside a shadow root. `meta()` keeps its keys; `SelectorStore` has `shadow_hosts()`, and `add_candidate()`, `set_meta()` and `quarantined()` take `shadow_hosts=`. A 0.9.0 process drops the key's `shadowHosts` when it writes the store, runs a heal's chain on Playwright as Playwright does, inside the host, and refuses it on Selenium. Drivers can have `shadow_html()`, `shadow_inventory()` and `shadow_matches()`, take `ShadowHost` steps at the end of a frame chain and `hosts=True` in `fingerprint()`; the built-in ones do, and a heal inside a shadow root never runs on a driver that doesn't. A `heal.page.get_by_*()` call whose element is inside an open shadow root, which 0.9.0 left unhealed once renamed, now heals there from its fingerprint.
- The fingerprint read looks a form field's `<label for=...>` up in the element's own shadow root when it is inside one, as the HTML of that shadow root has it; on the page it reads as before.
- A TypeScript package for Playwright Test is in `js/`, to be published to npm as `mendwright` 0.1.0 ([js/README.md](https://github.com/saadbuilt/mendwright/blob/main/js/README.md)). It reads and writes the same `.mendwright/overrides.json`, and nothing in the Python package changed: the sdist and the wheel leave `js/` out.

### Changed

- The journal grows by one line for each heal that did not apply (`heal.declined`) and each flow mendwright stopped (`flow.stop`), and each line by the run id. `mendwright report` and `mendwright fix` ignore them, and so does 0.9.0.
- `mendwright doctor` shows `MENDWRIGHT_WEBHOOK_URL` as its scheme and host only, and only when `mendwright notify` takes the URL, else why not, masks the value of any variable whose name holds `WEBHOOK` in its error text, and masks secret values in the variables it shows too.

## [0.9.0] - 2026-10-17

- `heal.page.get_by_role()`, `get_by_text()`, `get_by_label()`, `get_by_placeholder()`, `get_by_alt_text()`, `get_by_title()` and `get_by_test_id()` heal on Playwright, sync and async, with `mendwright.open(page, heal_get_by=True)`, `MENDWRIGHT_HEAL_GET_BY=1` or `pytest --mendwright-heal-get-by` (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#get_by-locators)). It is off by default, and then nothing changes. A call is saved under a key written as the call, such as `get_by_role("button", name="Sign in")`, and `mendwright.get_by_key()` builds one for `destructive_keys=`, `expect_values=` and seed files. Those, and `heal.present()`, read the same call written in another spelling, such as `get_by_role('button', name='Pay')`, as its key. A call written on an object, such as `page.get_by_role('button', name='Pay')`, is a key of its own, and mendwright logs a WARNING with the call's key for one in `destructive_keys=`, `expect_values=` or a seed file. A call that matches nothing for `timeout_ms` is healed from the fingerprint mendwright recorded when it last matched, with the usual checks, and a heal of a `get_by_role()` call must also have the call's ARIA role on the live page. No model is asked for a call, so no page leaves the machine for one, and a call that never matched is not healed. A call that matches several elements, or one hidden element, goes to Playwright as written, and a saved heal answers only while the call matches nothing. With it on, a missing element waits `timeout_ms` (10 seconds by default), not Playwright's timeout, and the error is an `AttentionRequired` that is also Playwright's `TimeoutError`; registered interruptions are handled by the step and logged before the call's key. Not healed: chained calls, `.first`, `.last`, `.nth()`, `.filter()`, `frame_locator()`, `get_by_role()` with `checked=`, `disabled=`, `expanded=`, `pressed=`, `selected=` or `include_hidden=True`, `is_visible()`, `expect()`, and a call that matches only inside an iframe. `mendwright fix` never rewrites a call: it lists the healed selector and where calls with the same arguments are. Drivers can have an optional `role_match()`; the Playwright ones do.
- `mendwright check` looks for drift before a run (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#checking-for-drift-before-a-run)). It opens the page where each key in the store was last found, in a headless Playwright browser, on a site you name with `--origin` or `--base-url`: it never loads a site the store alone points to. There it looks at the key's saved selectors the way a run does: for the key of a `heal.page.get_by_*()` call, the call itself first and its saved heals only while it matches nothing, so a call that matches several elements, or one hidden element, is `refused`, since a run hands it to Playwright as written, and a call is never `needs model`. It never clicks, types or presses anything, never calls a model, and saves nothing: the store is opened read-only, no journal line is written, and no storage state is written back. Each key gets one result: `ok`; `ok (heal)`, where only a saved heal matches and `mendwright fix` can put it in your code; `wrong role`, where the selector matches one visible element of another control role, which a run acts on all the same; `would heal`, where the fingerprint tier, or a match inside one iframe, finds the element and it passes every check of a heal; `needs model`; `refused`, where a run would stop with `AttentionRequired`, in the run's own words; or `not checked`, with the reason; a list that matches nothing names the list heal that waits for it in `mendwright lists`. A key that broke makes it exit 1, a key it couldn't check exits 3 (`--allow-unchecked` accepts that), and a store or browser it can't open exits 4. `--fail-on unhealable` exits 1 only for keys a run can't get past alone, and `--strict` also counts keys that match only through a heal. A page that answers HTTP 400 or more, goes to another page such as /login, or shows only a sign-in form is reported as not checked; `--storage-state FILE` passes a sign-in. Pages whose path reads as an action, such as /account/sign-out or /cart/empty, aren't loaded unless `--load-page` names them. `--cookies reject` closes a consent banner first, the only click it can make. `--format md` and `--format json` (with `"schema": 1`) suit CI, and `--workers N` checks several pages at once. `heal.drift()` (and `await heal.drift()` on `mendwright.aio.open()`) does the same on the page your script is on, with no navigation, on Playwright, Selenium and your own drivers, and returns a `mendwright.drift.DriftReport`.
- `heal.locator_all(key, selector, nonempty=True)` says that a list always has items at that point, such as the rows of a cart your test just filled (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#lists-that-always-have-items-nonemptytrue)). When none of its selectors matches, mendwright waits `timeout_ms`, then looks for the list from its list fingerprint, and never uses what it finds: it saves it in `overrides.json` as a proposed list heal and raises `AttentionRequired` with the new selector, where the list was and where the group it found is, and it says so when the heading or the container is not the same. `mendwright lists` shows what waits, with the first items of both; `mendwright lists accept KEY ID` accepts one and `mendwright lists reject KEY` rejects it; `mendwright fix --apply` writes an accepted one into your code, and only then does `heal.locator_all()` use it, as your selector; for a key whose selectors come from a seed file, the message, `mendwright lists` and `mendwright report` say to put it there, and the seed file's row then takes it over. mendwright proposes only a group of 2 or more elements that holds 2 of the 3 items it recorded, isn't under another heading or in another part of the page than the list was, isn't picked by a class or name that says a state the list didn't have (completed, done, saved, archived and a few more), and passes the live check. A list heal you accepted is quarantined when the selector it replaced matches again, and `mendwright fix` writes it only in place of that selector, never when your last run passed other selectors for the key (another page's, or one you fixed by hand) or one of them matched after it was found, so `mendwright fix` never writes it over a selector that works. Where the list sits and its heading are recorded once a call with `nonempty=True` has matched it, so add it while the list still works. Without `nonempty=True`, lookups give and raise exactly what they did in 0.8.0. New: the journal events `heal.held` and `heal.accepted`, and the candidate statuses `proposed` and `accepted`, which 0.8.0 ignores; a 0.8.0 run on the same store drops a proposal's evidence, and the list is proposed again. No model is asked about a list. `nonempty=` takes only `True` or `False` (`TypeError`), and not with `optional=True` (`ValueError`), checked before anything touches the page. The pytest plugin's summary names the keys with a list heal that waits for you to check it. Drivers can take `place=` in `list_fingerprint()` and have an optional `list_items()`; the built-in ones do.
- A GitHub Action, `uses: saadbuilt/mendwright@v0.9.0` (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#open-a-pull-request-with-the-fixes)), opens a pull request with the heals your tests confirmed. It runs in a job of its own after your test job, takes the store and journal from that job's artifact, runs `mendwright fix --apply` on the commit the tests ran on, and opens one pull request per base branch, on `mendwright/fix/<base>`, or updates the open one. The body lists each selector written back, how it was found (fingerprint or model), what confirmed it (a passing test and its node id, `expect=`, `expect_value=` or `confirm(True)`), and what was left alone and why. It writes only confirmed heals and the list heals you accepted with `mendwright lists`, never a `get_by_*` call, commits only the tracked files `mendwright fix` changed and never anything under `.github/`, runs no git hook, pushes with `--force-with-lease`, and never pushes over commits it did not make. With the same changes it pushes nothing, it never lets an older run overwrite a newer one, it does not reopen a pull request a person closed, and after a run whose tests passed it closes one whose changes are no longer needed, with a comment. It runs on `push`, `schedule`, `workflow_dispatch` and `workflow_run` from those in the same repository, does a dry run on `pull_request` with `dry-run: true`, skips other runs, and refuses `pull_request_target` and a checkout that is not the tested commit. It needs `contents: write`, `pull-requests: write` and `actions: read`. It installs one hash-pinned lxml wheel into a venv of its own, builds nothing, and runs mendwright from its own tag.
- `mendwright fix --format json` and `--format md`, and `--out FILE`. The JSON has a stable code for each key or file left alone, `get_by_call` for a `heal.page.get_by_*()` call and `list_proposed` for a list heal that waits for you among them, and says that an accepted list heal written back was found by its list fingerprint and accepted with `mendwright lists accept`; the Markdown is what the Action puts in the pull request.
- `mendwright fix --destructive-key KEY` treats keys as destructive, as `mendwright.open(destructive_keys=...)` does, which the store does not save: a list heal you accepted for one is not written either, and a `get_by_*` call written in another spelling stands for the call's key. An accepted list heal that is not an XPath lxml can compile, or whose CSS form mendwright doesn't build, is never written, as for any heal.
- `heal.canary` says what confirmed or refused a heal: `by` is `test` (with the node id in `test`), `expect`, `expect_value`, `confirm`, `action` or `destructive`. `HealCoordinator.confirm()` and `confirm_pending()` take `by=` and `test=`; a subclass that overrides `confirm()` without them still works, and so does a `confirm_pending()` or a journal's `canary()` written for 0.8.0.

### Changed

- `mendwright.selectors.classify()` returns `'get_by'` for a string written as a `get_by_*` call, and `check_syntax()` raises `InvalidSelector` for one, so `heal.locator()`, `heal.locator_all()`, `heal.interrupt()` and `heal.step(when=...)` refuse it as a selector. `heal.locator()`, `heal.locator_all()` and `heal.interrupt()` raise `ValueError` for one as a key. Those strings are how mendwright names `heal.page.get_by_*` calls.
- The store saves the address where each key's element was last found, `lastUrl`, next to `lastPage`: scheme, host, port and path, with record ids, tokens, email addresses and long names as `*`, and no user info, query or fragment. Keys found only on the site root get one too; a key also found on another page keeps that page's address. It isn't saved for `file://` pages, or for a healer opened on a Playwright `Frame` or on a Selenium driver switched into a frame. The first run after the upgrade writes the store once for each key it finds; later runs don't write for it, also when a test app starts on a new port. `locator()` saves a new page, step and address in one write. 0.8.0 reads such a store and drops `lastUrl` when it writes one. `load_store()` and `SelectorStore` take `read_only=True`, and `SelectorStore` has `last_url()` and `snapshot()`.
- Run `mendwright fix` from 0.9.0 on a store 0.9.0 wrote: 0.8.0 reads a call key's text as CSS.
- `mendwright fix`'s reason for leaving a list heal saved by a build of 0.8.0 before its release alone says it can be another list and that `nonempty=True` gets one proposed.
- `mendwright fix` no longer rewrites the selector passed to `heal.interrupt()` or the landmark passed to `heal.step(when=)` when it equals the old selector of a healed key: written there, another key's heal would make the interruption act on that key's element. It lists them with the selector to check. This holds for a string written in the call and for one that reaches it through a name in the same file (a constant, a class constant, a dict or list, a parameter of a function you define with `def`); a string from another module, a `lambda`'s parameter and a function's return value are not followed.
- `mendwright fix` no longer writes a heal that is not an XPath lxml can compile, or whose CSS form is not one mendwright builds, since mendwright saves no such heal. It lists the key.
- `mendwright fix` lists a key whose newest heal was quarantined and that nothing has matched since.
- `mendwright fix` skips `.github` folders, also when `--path` names one, leads into one through a link or junction, or names one in another case. The folder it runs in and those above it count only when `--path` names them, and the action refuses a `working-directory` inside `.github`.
- `mendwright report --format json` counts `held` in `journal.counts` and `per_key`, and gives a list heal's candidate `list`, `proposal` and `accepted`. The text, Markdown and HTML reports of a store with no list heal and a journal with no `heal.held` are as in 0.8.0.
- `mendwright report --format md` writes its code spans as `mendwright fix --format md` does: a selector that holds two backticks in a row gets a code span that holds it, control and bidirectional characters show as `\uXXXX`, a space at either end of a value is kept, and an empty value shows as (empty).

## [0.8.0] - 2026-10-16

- `heal.interrupt(key, selector, run=fn)` handles an interruption that needs a whole form with a function of yours (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#interruptions-that-need-a-form)): a session-expired popup that asks you to sign in again, a form for your address or postcode, a confirmation with two fields. When `selector` matches one visible element, at the same moments as any interruption (a lookup misses, before an action, after an action was intercepted, and from Playwright's overlay handler), mendwright calls `fn(heal.page)`, or `fn(heal.driver)` on Selenium, instead of one action, then waits for the element to go away as after an action. One still there counts as handled, so a step handles at most 3 and the overlay handler leaves it alone after 3 in a row, as before. The function's own actions never handle its own interruption, so it never runs itself, but they do handle the other registered ones, such as a cookie banner that opens over its form. Nothing dismisses a popup while it runs, and Playwright's overlay handlers stay out of its actions as they stay out of mendwright's own clicks; when Playwright's handler calls it, Playwright runs no handler inside it. On `mendwright.aio.open()` it is an async function, awaited on the event loop with no time limit (or a plain one that returns an awaitable, else `TypeError`), and its calls go ahead without the healer's lock, which the step that called it holds. Cancelling the step, for example with `asyncio.wait_for()`, cancels the function too, with one WARNING and a `flow.interrupt` event with `"outcome": "failed"` and `"error": "CancelledError"`. What it raises is raised as it is, after one WARNING and a `flow.interrupt` event with `"outcome": "failed"` and the error's type; an `AttentionRequired` from it is never taken for a miss of the step, so nothing is healed or skipped. When Playwright's overlay handler called it during a step mendwright routes, the error can't reach the step's action, which goes on, and the step raises it once that action ends, when it goes through or its timeout runs out, without a second call; before an action mendwright doesn't route, the error can't reach the action, and the handler leaves the interruption alone until mendwright sees it gone or the page navigates. Inside the handler, Playwright gives the function the time of the action it interrupted. When it takes longer, that action gives up while the function goes on: a step mendwright routes then waits for the function and never calls it a second time while it runs, and, when the action was its own, raises the function's error, or the action's `TimeoutError` when the function returned. On newer Playwright releases, 1.55 among them, the function's own actions after that point wait for the handler, which is the function itself, and fail with `TimeoutError`. The log line ends `with relogin()`, and `flow.interrupt` has `"action": "run"` and the function's `__name__` as `function`. The `InterruptionLoop` message, and the WARNING for one the overlay handler leaves alone after 3 times in a row, tell you to check that `relogin()` closes it, not its `action=`. `run=` with `action=` or `args=`, a `run=` that isn't callable, `heal.interrupt(key, None, run=...)` and an async function on the sync healer raise `TypeError` before anything touches the page. `action=` now defaults to `None`, which is a click, so that `action="click"` with `run=` is caught too. It works on Playwright, sync and async, and on Selenium. The keys the function looks up are not saved with the step `run_steps()` runs. `mendwright report --format html` names the function, and lists one that raised as an interruption that failed, which it doesn't count as handled.
- On sync Playwright, Playwright's overlay handlers stay out of mendwright's own lookups, as they already did on `mendwright.aio.open()`, whose lock kept them out. The lookup's scroll runs Playwright's check, and the handler used to handle a registered interruption there; now the step handles it itself, right after, before its action or read, and logs it before the same key. So a `run=` function is called by the step, with no time limit, rather than inside Playwright's handler with the scroll's timeout. The first read of a `heal.locator()` proxy (`text_content()`, `inner_text()`, `inner_html()`, `get_attribute()`, `input_value()`, `is_visible()`, `is_hidden()`, `is_checked()`, `is_enabled()`, `is_disabled()`, `is_editable()`) handles the registered interruptions the page shows first, as an action does, unless one of its actions came first, and so does the first read of an element of `heal.locator_all()`, once for the whole list. Later reads don't look again, so the check runs once per lookup, as the lookup's scroll did on 0.7.0, and a step that only reads still closes a cookie banner, logged and journaled before its key. Each read of `heal.page` and `heal.page.locator(selector)` that goes through a proxy is a lookup of its own and looks each time: with `cookies=`, on a page of 2,000 elements in Chromium, that added 15 to 45 ms to each such read. `is_visible()` on `heal.page` and its locators still answers at once and handles nothing. On `mendwright.aio.open()`, whose lookups never handled an interruption, the reads now do the same.
- An interruption whose selector matches several elements, and is skipped for it (a CSS or Playwright selector, or an XPath whose first 5 matches are hidden), is named in one WARNING per key and page when none of its selectors finds it, with how many elements it matches and, when exactly one of them is visible, up to two selectors that match only that one, checked on the page: `interruption 'cookies' was skipped: its selector '.cookie-accept' matches 2 elements, ... such as '#accept-all' or 'role=button[name="Accept all"]', which each match one visible element on this page.` They are built from that match: CSS from its id, test id or other attributes, `role=button[name="..."]` (`role=link[name="..."]` for a link) and `text="..."` on Playwright for a short text, and an XPath of its tag and text. When more than one of the matches is visible, such as a chat widget's Close button and the banner's own, it names none and says so, since a selector built from the first could be the wrong element. When none fits, the WARNING says what to look for, and that none of the matches is visible, when that is so. The same goes for a step's landmark that matches more elements than mendwright looks at (the first 5, or on Selenium the first of a CSS selector's), none of those visible, when the step doesn't show: `step 'payment' did not show: its landmark '.step-title' matches 2 elements, ...`. These used to be skipped without a word. The `cookies=` preset's own selectors are never named. Drivers can have an optional `visible_match(selector, frame_chain=())`, which returns `describe()`'s result for the first visible match plus `"visible"`, how many of the matches are visible, counted up to 2; the built-in ones do.
- Reads that check what they return (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#checking-what-a-read-returns)): `heal.locator(key, selector, expect_value=...)` says what a read of the element must return when it was found through a selector a heal saved, in this run or an earlier one: `"money"`, `"number"`, `"integer"`, `"percent"`, `"date"`, `"email"` or `"url"`, a compiled regular expression (searched, as `re.search()` does), or a callable that takes the value as a `str`. `mendwright.open(expect_values={key: check})`, and `mendwright.aio.open()`, sets it for keys, the keys of `heal.page` (the selector) and `heal.driver` (`by=value`) included. The reads are `inner_text()`, `text_content()`, `input_value()` and `get_attribute()` on Playwright, sync and async, and `text`, `get_attribute()` and `get_dom_attribute()` on Selenium. A value that passes confirms a heal made in this run, as `expect=` on an action does. One that fails quarantines the heal, with a `heal.canary` and a `heal.quarantine` whose `reason` is such as `expect_value: inner_text() is not money` (the value is never journaled), and the read raises `AttentionRequired` naming the key, the healed selector and the value, which is also logged as one WARNING. The quarantine blocks the element, so the next lookup heals again without it. A read through any other selector, such as the one in your code, is never checked. Numbers are read as most locales write them: `1,299.00`, `1.299,00`, `1 299,00` with non-breaking or narrow spaces, `1'299.00` and `1,29,999.00`, with a single `.` or `,` before exactly three digits read as a thousands separator, except in a currency with three decimals (`KWD`, `BHD`, `OMR`, `JOD`, `TND`), where that `.` is the decimal point (`KWD 1.250` is 1.250) and that `,` could be either, so `parse_money()` gives `None` for it, though it passes `"money"`. Money needs a currency sign (`US$` and the like included) or a currency code or abbreviation before or after the amount: `$1,299.00`, `1.299,00 €`, `129 kr`, `CHF 12.50`, `129,-`. `mendwright.values.parse_money()` and `parse_number()` give the amount as a `Decimal`. A date is numeric (`2026-10-15`, also with a time as ISO 8601 writes it, such as `2026-10-15T10:00` or `2026-10-15T10:00:00+02:00`, `15/10/2026`, `15.10.2026`, `2026年10月15日`) or has the month's name in English, German, French, Spanish, Italian, Dutch or Portuguese, and must exist. An `expect_value=` mendwright doesn't take raises `TypeError` or `ValueError` before anything touches the page.
- Lists (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#lists)): `heal.locator_all(key, selector=None, *, role=None, timeout_ms=None, poll_ms=200, optional=False)` gives an `ActionProxy` for each element a list selector matches, such as the cards of a product grid; in `mendwright.aio` it is `await heal.locator_all(...)`. `heal.page.locator(selector).all()` and `heal.driver.find_elements()` behave as in 0.7.0, give what the real call gives and never wait, heal or save anything, so a list that matches nothing is `[]` at once. Each time a `heal.locator_all()` lookup matches two or more elements, mendwright records a list fingerprint in one round trip, saved as `listFingerprint` in `overrides.json`, and the first lookup of a key saves it with its selector, first success and page in one write: the fingerprints of three of the items, their shapes (the tags inside each and of its children), how many there were, and their common container. mendwright never heals a list whose selectors all match nothing, since an emptied list can't be told from one whose selector broke: once every item of a cart moved to Saved for later, the page can be what a redesign that renamed the rows would give, but for a class name or a heading's text, and a heal there gave a loop that deletes the cart's rows the items saved for later. So a redesign that renames a list's items makes its lookup raise until the selector in your code is fixed. A list with a list fingerprint that matches nothing waits `timeout_ms`, handles the registered interruptions, and raises `AttentionRequired`, which says that either the list is empty at this point or its selector broke; it looks for no other list, asks no model and saves nothing. A list never seen with two or more items, or one passed `optional=True`, gives `[]` at once when nothing matches, and so does every list while the fingerprint tier is off (`fingerprint=False`, `MENDWRIGHT_FINGERPRINT=0` or `MENDWRIGHT_DISABLE=1`). A list lookup uses no heal saved under its key, so a heal of the first card that `heal.locator()`, a `heal.page` shortcut or `heal.driver.find_element()` made under the list's key never answers `heal.locator_all()`, and the elements' actions and `confirm()` report nothing for it. The elements' actions handle interruptions and popups, and their reads are never checked against `expect_values=`. `mendwright fix` never writes a heal of one element into a key that `heal.locator_all()` looks up as a list, which would make the list that one element: it names the key and the healed selector instead. Drivers can have optional `handles()` and `list_fingerprint()`; the built-in ones do.

- `mendwright fix` writes confirmed heals back into your code (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#mendwright-fix)). It prints a diff of the string literals it would change, and `--apply` writes them, checking that each Python file still parses and changed only in the planned strings. It leaves alone keys marked destructive, heals inside an iframe, unconfirmed heals (unless `--include-unconfirmed`), keys whose old selector is a bare word, a key in `heal.locator(key, ...)` and `role=` or `text=` values, and a selector passed where only CSS runs, such as `By.CSS_SELECTOR`, and lists each with the reason.
- `mendwright report --format html` writes one self-contained page (no scripts, nothing loaded from the network) with the keys, recent heals, flow events and quarantines, and `--out FILE` writes any format to a file.
- `mendwright doctor` says whether the fingerprint tier is on, and `--json` has a `fingerprint` entry.
- `HealEvent` has a `source`: `"fingerprint"`, `"model"` or `"intent"`. The journal's `heal.proposed`, `heal.rejected` and `heal.applied` carry the same `source`, and a fingerprint heal has `"provider": "fingerprint"`.
- Drivers can have an optional `fingerprint(selector, frame_chain=())`, which the built-in Playwright and Selenium drivers have.
- The benchmark runs the fingerprint tier first, as `mendwright.open()` does. `--no-fingerprint` measures the provider alone, and the results show which tier made each heal.
- Flow changes (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#flow-changes)):
  - `heal.interrupt(key, selector, action="click", args=(), role=None)` registers a step that can show up at any point, such as a cookie banner, a newsletter modal or an "are you still there?" dialog. mendwright handles it when it is in the way of a step (the step's element is missing, the page shows it before an action, or an action fails because something covered the element), then goes on with the step. A failed action is retried once, and only after an interruption was handled, never when Playwright's call log says the action was already done. At most 3 are handled per step. An interruption is never healed, and a later `heal.locator()` for its key is skipped when the element isn't there. When an action fails because its element was covered or couldn't be reached and no interruption matched, one WARNING names the ones mendwright looked for, since one whose selector no longer matches is the likeliest cause.
  - `mendwright.open(page, cookies="reject")` or `cookies="accept"` registers an interruption for the consent banners of OneTrust, Cookiebot, Didomi, TrustArc, Usercentrics, Quantcast Choice, Osano, cookieconsent, CookieYes and Complianz, with a fallback for other banners. The fallback acts only inside a short element that mentions cookies and holds no text field or navigation, so a consent screen that isn't about cookies (an OAuth Allow, a terms step) or a button such as Close account is never clicked. It is off by default.
  - `heal.locator(..., optional=True)` skips a step whose element isn't there instead of healing it. Proxies have `.present`, which is False for a skipped step, and its actions do nothing.
  - The prompt tells the model it may answer `{"xpath": null, "reason": "..."}` when no element on the page fits the step, and not to pick an element that is only similar. Providers report that as "the model says no element on this page fits: <reason>", and the reference gateway passes it on. The prompt also names the page path and the path where the key was last found.
  - All of this works the same in `mendwright.aio`, where actions awaited together look for interruptions one at a time.
  - New journal events: `flow.interrupt`, `flow.skip` and `flow.page_guard`.
- `mendwright demo` shows a cookie banner that now opens first and covers the form, handled as a registered interruption. `StandInPage` takes a `url=` and knows an overlay that blocks clicks until it is closed.
- An accuracy benchmark in `benchmarks/`: 47 cases where a redesign breaks a selector (12 of them where the right answer is no heal, 4 of those a step that moved to another page), a harness that runs them through `mendwright.open()` with any provider or a model-free baseline, and the baseline results. It is not part of the package. See [docs/benchmark.md](https://github.com/saadbuilt/mendwright/blob/main/docs/benchmark.md).

### Changed

- `heal.page` on a Playwright healer is now a stand-in for the page (`HealingPage`, or `AsyncHealingPage` in `mendwright.aio`), and `heal.driver` on a Selenium healer is a stand-in for the WebDriver (`HealingDriver`). They pass `isinstance()` checks, and `.native` is the real page or driver. `heal.driver` on Playwright and `heal.page` on Selenium are as before.
- With no provider configured, a broken selector heals when its fingerprint finds the element with confidence. The `mendwright.open()` warning, `mendwright doctor` and the pytest header say so.
- `overrides.json` now stores a `fingerprint` for every key whose selector matched while the tier is on, not only for healed keys, and an `intent` when you pass one. The file is written when a fingerprint changes. [SECURITY.md](https://github.com/saadbuilt/mendwright/blob/main/SECURITY.md) lists what a fingerprint holds.
- A fingerprint heal doesn't count toward the hourly rate limit, and isn't reported to the provider's `report_outcome()`.
- A key is no longer healed on a page other than the last few its element was found on. The store saves those pages (`lastPage` and `pages` in `overrides.json`, at most 5; numbers, uuids and other generated ids in a path count as one page), and such a heal is declined before any model call with an error that says the flow looks changed. Pass `heal_across_pages=True` to `mendwright.open()` to heal there anyway, for example after a redesign that only changed the URL. Pages loaded with `page.set_content()` (`about:blank`) are never compared.

## [0.3.0] - 2026-10-11

First public release. Earlier versions were developed privately as selfheal and never published.

- Drivers for Playwright (sync and async, including patchright and camoufox) and Selenium, behind one `mendwright.open(page)`. `heal.locator(key, selector)` takes XPath, CSS or Playwright selectors. A heal is always an XPath.
- Providers for Anthropic, OpenAI and compatible APIs, Gemini, Bedrock, LiteLLM, Ollama and your own gateway. `auto_provider()` picks one from the environment, and there is no default model. `ANTHROPIC_BASE_URL` and `OPENAI_BASE_URL` are honoured for proxies and compatible hosts.
- Local checks before a heal is used: not an index-only path, not quarantined or superseded for the key, one match in the captured HTML, the step's role, and one visible match on the live page that still has the role. A heal whose action fails is quarantined, and the quarantine blocks the same element, not just the same selector string.
- Keys you mark as destructive are never healed and never sent to a model: `destructive=True` in `heal.locator()`, `mendwright.open(destructive_keys=...)`, or `"destructive": true` in a seed file. mendwright doesn't guess this from the key or the page.
- Page capture removes scripts, styles, comments and head metadata, and redacts values, URLs and long numbers, including in broken selectors and expected text. Direct providers have an hourly rate limit and an optional spend cap.
- A pytest plugin: the `heal` fixture, an overridable `mendwright_provider` fixture, and `--mendwright-strict`, which also fails reruns from pytest-rerunfailures. Heals from a passing test are confirmed.
- The `mendwright` command: `demo` (offline, or `--live` with the model from your environment), `doctor` and `report`.
- Heals are saved in `.mendwright/overrides.json`, with a journal next to it. A corrupt store raises instead of being overwritten. Each applied heal prints one line to stderr.
- Python 3.10 to 3.14, with lxml as the only dependency.

### Changed

From the private builds. If you never used them under the name selfheal, you can skip this.

- On Selenium, the handle for a candidate inside an iframe is a `FramedElement`. `driver.execute_script()` and `ActionChains` need `el.in_frame(lambda e: ...)` to get an element that still works in the frame (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#selenium)).
