# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and version numbers follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
While the version starts with 0, a minor release can change the public API.

## [Unreleased]

- `mendwright.open(page, dismiss=True)` (and `mendwright.aio.open()`) dismisses a popup nobody registered when it covers the element of an action: a newsletter or discount modal, a prompt that can be skipped, an app-install banner, a survey, a chat invite, a consent banner when `cookies=` isn't set (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#popups-mendwright-wasnt-told-about)). Registered interruptions come first. Before each action, once those the page shows are handled, mendwright asks the browser what is on top at the middle of the element (`document.elementFromPoint`), and after an action fails because something covered it, it looks again when no registered interruption is on the page. It acts only on a dialog, or a fixed or sticky element that takes pointer events and covers at least a quarter of the window, that doesn't hold the element, so a sticky header, a toast and the popup you are typing into are left alone. It presses Escape, only while the keyboard focus is on the page's body or in the popup and not in an iframe (Escape goes to the focused element, and would clear a search field the script filled), then clicks the popup's close button, then a button that declines (No thanks, Not now, Skip, Reject, ... with at most a few harmless words more), and looks again after each. It never clicks a button whose label (hidden text included) says accept, subscribe, sign up, yes, continue (unless it says continue without and what it leaves out, such as an account), pay or the like, also as part of a longer word such as payment, or has a digit or a currency sign; nor a link that goes somewhere, a button inside one, a button in a label, or a button that submits or resets a form; and it never types, checks or selects. With `cookies="accept"`, a consent banner the preset doesn't know is left alone with a WARNING, since declining it would turn the consent down. Each dismissal logs one WARNING, writes a `flow.dismiss` journal event and is listed in `handled_interruptions` under the key `<popup>`, with the new `popup`, `how` and `label` fields of `InterruptionEvent`. A popup it can't dismiss is named in one WARNING that says what mendwright pressed and clicked, with a `flow.dismiss` event whose `outcome` is `failed` when it did anything, and the action fails with the browser's own error; one that comes back each time it is dismissed raises `InterruptionLoop` once the step has handled 3. With `dismiss=True`, `heal.page`'s `get_by_*` locators, locators with options, chained locators, `frame_locator()`, `and_()`, `or_()`, `.first`, `.last`, `.nth()` and `.filter()` come back as `GuardedLocator`s: the real locators, not healed, whose actions get the same checks. It works on Playwright, sync and async, and on Selenium, inside iframes too. Not covered: the page or driver passed to `open()` and the locators built from it, `page.mouse`, `page.keyboard`, `dispatch_event()`, `ElementHandle`s, `Frame`s, `Locator.all()`, page methods that aren't `heal.page` shortcuts, `ActionChains`, and the elements that `execute_script()` or `switch_to.active_element` return. It is off by default, and then mendwright makes no browser call for it; with it on, each action costs one more. `--mendwright-strict` doesn't fail a test for a dismissal, as for a handled interruption. `mendwright report --format html` lists dismissals, and popups it gave up on, with the flow events.
- Interruptions (`heal.interrupt()` and `cookies=`) are also handled before actions that mendwright does not route, not only before its own steps. On a page whose selectors still work, a consent banner over the form used to stop the script:
  - On Selenium, `find_element()` returned the bare `WebElement`, so `click()` failed with `ElementClickInterceptedException` and the banner stayed. It now returns a `HealingElement` for any `By`, and so do `find_elements()` and `find_element()` or `find_elements()` on an element. Its `click()`, `send_keys()`, `clear()` and `submit()` handle an interruption that covers the element first, and try a click that something covered once more after handling one, as `heal.locator()`'s actions do; otherwise they raise Selenium's own error. It passes `isinstance(el, WebElement)`, is equal to the element and hashes the same, and works with `execute_script()`, `ActionChains` and `expected_conditions`. With no interruption registered and `dismiss` off, an action makes no browser call besides the element's own. Not covered: `ActionChains` actions, the elements that `execute_script()` or `switch_to.active_element` return, and a banner on the page around a frame the script switched into itself, which mendwright cannot see from inside the frame (the WARNING after a covered click there says so).
  - On Playwright, `get_by_*` and chained locators, `.first`, `.nth()`, locators with options and the page's own methods went to the real page and timed out on the banner, and a banner that opened after the check before a routed action held it for Playwright's whole timeout. From Playwright 1.42, on a `Page` (sync or async), mendwright registers each interruption with `page.add_locator_handler()`, so Playwright hands over to mendwright before each locator or selector action on the page (`click`, `fill`, `check`, `hover` and so on) and while one waits. Playwright runs no handler before `page.mouse` and `page.keyboard` actions, `dispatch_event()` or an action with `force=True`. An action mendwright did not route is logged as handled before `'<page action>'`. The handler's locator is narrowed to the first visible match: Playwright checks it in strict mode, and a banner with both a Reject and a Close button would otherwise fail every action. It is registered with `no_wait_after=True` (from 1.44), so an action never waits on an overlay mendwright decided to leave alone, such as one still there after it was handled 3 times in a row (one WARNING; it is handled again once mendwright sees it gone or the page navigates or loads). A selector the browser cannot parse, which would fail every action on the page in Playwright's check, is left out of the handler with a WARNING: `heal.interrupt()` checks CSS only in the browser, so `'button:contains("Close")'` passes it. A page keeps one handler per key however many healers are opened on it: a healer that registers the same selectors joins it, and other selectors replace it (Playwright 1.44 and later remove the old one from the page, unless the handler of another key watches the same selectors).
- `heal.interrupt(key, None)` removes an interruption, the `cookie_banner` of `cookies=` included, and on Playwright 1.44 and later its overlay handler, once no other healer of the page has registered it. A healer you stop using is freed only when Python's garbage collector next runs, and its handler acts until then, so call it when a page outlives the healer.
- The fallback of `cookies=` checks for a banner before it reads each button's label, so on a page without a banner it takes about a quarter of the time it did. Playwright now runs it at least twice per action.
- Steps in any order (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#steps-in-any-order)): `heal.step(name, when=None, fn=None, *, url=None, last=False, optional=False)` registers one step of a flow, such as a checkout, as a decorator or with the function as `fn`, and `heal.run_steps()` runs whichever step the site shows, each once, until the `last=True` step ran (or, with none, every step that isn't optional), and returns their names in the order they ran. A flow whose site now asks for the card before the address, puts two steps on one page or sometimes shows an upsell (`optional=True`) runs without a change to the script, and so does one that drops a step when the final step has `last=True` (the dropped step is named in a WARNING; with no last step, `run_steps()` waits for it and stops with an error that says the site may have dropped a step). `when` is a landmark, one selector or several, any visible match of which shows the step; `url` is a pattern for the page's path, normalized as for the page guard, instead or as well (one that starts with `*` is kept as written, so `*/payment*` matches `/payment`). Landmarks are never healed. Steps stay on the healer for every later `run_steps()` call. Steps that show at the same time run in the order they were registered, and the last step only when no other shows. The function gets `heal.page` on Playwright and `heal.driver` on Selenium, so its selectors heal as usual. While a step runs, a key found during that step in an earlier run heals on the page the step showed on, whatever its address: the store saves the steps each key was found during on that step's page (`steps`, next to `pages`), and there the page guard declines only keys never found during the step that runs, so a field renamed in a step that also moved heals there. Once the step's function goes to another page, such as with its own submit, and outside `run_steps()`, the guard is unchanged, so a lookup after a step's submit is never healed onto the next step's controls. While `run_steps()` waits, registered interruptions the page shows are handled, up to 3 in each wait, logged as before `'<next step>'`, and one whose action fails isn't tried again in that wait while the others still are; popups are dismissed by the steps' own actions, with `dismiss=True`, as before. It raises `AttentionRequired` instead of guessing when a step that ran is on the page again with no new step for the whole timeout (a declined card: the step is never run twice; when it shows on another page than the one it ran on, the message says the site probably added a step that shows part of it), when no step shows (naming the page and every landmark, and saying to add the step with `heal.step()`), and after 3 times as many step runs as steps; an error in a step's function is raised as it is. Each step run logs one INFO line and writes a `flow.step` journal event (`position`, `registered`, `page`, `seconds`, `outcome`), a step that runs after steps registered behind it logs one WARNING ("ran 'payment' before 'shipping': the site changed the order of the steps"), and so does each step that isn't optional and never showed once the last step ran. Arguments that can never work raise at once, before anything touches the page, a Playwright selector in `when` on Selenium included. `--mendwright-strict` doesn't fail a test because the steps came in another order. It works on Playwright, sync and async (`AsyncHealer.step()` takes async functions, or plain ones that return an awaitable, and `await heal.run_steps()`; it raises `TypeError` for a plain function that returns anything else, since `heal.page`'s calls there are coroutines that would never run), and on Selenium. The HTML report doesn't list `flow.step` events yet.

### Changed

- When an action fails on an element that `heal.driver.find_element()` looked up through `heal.locator()`, a heal made for it is quarantined, as for a proxy action. Actions on the bare `WebElement` it used to return confirmed nothing. Elements of the other `By` values and of `find_elements()` were never healed, and their actions confirm and quarantine nothing.
- A `StaleElementReferenceException` no longer quarantines a heal, on `heal.locator()` and on `heal.driver`: it means the page re-rendered the element after it was found, which says nothing about the heal. It used to quarantine a correct heal, and the next lookup of the key then failed.
- On Selenium, the check before an action, of `heal.locator()` and of the elements `heal.driver` finds, handles an interruption only when something covers the element where a click on it lands (or when that can't be told, outside the viewport or inside an iframe). A step of your own on the interruption itself, such as the banner's Reject button, now goes ahead. Handling the banner first used to remove the button, and the click failed with `StaleElementReferenceException`. If the action fails because something covered the element after all, the interruptions are handled and it is tried once more.
- On Playwright 1.42 and later, with `cookies=` or `heal.interrupt()`, Playwright hands over to mendwright before auto-waiting assertions, `wait_for_selector()`, `Locator.wait_for()`, element screenshots and `aria_snapshot()`, and before each locator action on the page, the ones on the banner itself included, on `heal.page` and on the page itself. `expect(page.locator("#cookie-banner")).to_be_visible()` and `page.wait_for_selector("#cookie-banner")` now fail, because mendwright closes the banner first, and a step of your own that clicks the banner through `get_by_role()` or another locator mendwright does not route finds it gone and times out. Drop such a step, or write it as `heal.locator(key, selector)` with the interruption's key, which is skipped when the element isn't there.

## [0.6.1] - 2026-10-14

- A quarantine counts only in the place it was made. A selector quarantined inside an iframe no longer blocks an element that looks the same on the page, or the other way round. A heal made inside an iframe is saved with its `xpath=` prefix written out, as a key followed into an iframe already was, so it never shares a row in the store with the same XPath on the page; heal rows that 0.6.0 saved inside an iframe are respelled that way when a store is read. `SelectorStore.quarantined(key, frame_xpath=...)` lists the quarantines of one place; a custom store without that argument still blocks everywhere, as before.

## [0.6.0] - 2026-10-13

- Iframes, one level down, without opening mendwright on the frame (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#iframes)). A key whose selector matches nothing on the page but one element inside one iframe is looked up in that iframe from then on, with no model call, where it used to stop with `AttentionRequired`. It goes through the live check, logs one line, and counts as a heal with source `frame` (`heal.applied` has `"source": "frame"` and the iframe's selector), so strict mode and the canary treat it like one. And a key last found inside an iframe heals inside it: the fingerprint tier and the model get the iframe's HTML, the checks run there, and the heal is saved with the iframe's selector, built from its id, name, title or `src` up to its query. A candidate with the same text saved in another iframe, or on the page, moves to where the new heal was checked. Works on Playwright, sync and async, and Selenium. Dry run, `MENDWRIGHT_DISABLE=1`, a `guard=` that blocks heals, a key marked destructive, a lookup quarantined before, a match in several iframes or elements, an iframe inside another, and an iframe with no id, name, title or `src` still stop, with the reason. On Selenium mendwright looks one level down only, and a driver switched into an iframe is left there. Fingerprints are now also read for matches inside an iframe. Drivers can have optional `frame_matches(selector)` and `framed(frame_selector)`; the built-in ones do.
- A heal for a key whose selector in your code is CSS also gets a CSS form, saved with the heal as `css`: `#id`, a test id, `tag[attr="value"]`, `tag.class`, two of these, or one inside a container with an id, test id, name, aria-label or class. It must match the healed element and nothing else on the captured page, and one element with the same outer HTML on the live page. `mendwright fix` writes it where your code has CSS, so a CSS selector stays CSS, including in `find_element(By.CSS_SELECTOR, ...)` and `querySelector()`, which used to be left for you to change by hand. `mendwright report` shows it. Heals still run as XPath. An element that only its text tells apart has no CSS form, and none is saved without a live page to check it on. In Java, Kotlin, C#, Scala and Swift a CSS form with a double quote in it is written escaped; where the escapes aren't known (Go, Rust, JSON) the place is listed instead.
- A page longer than the prompt allows is no longer cut at 60,000 characters. Before a hosted provider or a gateway gets the bundle, mendwright shortens text and attribute values over 200 characters, then leaves out the subtrees that look unrelated to the step, largest first, until the page fits: what shares no word with its key, old selectors, expected text, intent or saved fingerprint, and isn't of its role, a label or heading, or a control. Each run left out becomes a comment saying how many elements went, and a note at the top tells the model. While anything is left out, a proposal with a position in it (`[2]`, `last()`, `position()`) is refused, since positions in that copy don't match the page. The inventory keeps whole rows. `LocalModelProvider`, which reads the page itself, sets `wants_full_html = True` and gets it unchanged; a custom provider can do the same. `mendwright.fit` has the details.

## [0.5.0] - 2026-10-13

- mendwright's own local model for heals that never leave your machine. `LocalModelProvider` asks `mendwright-selector`, Qwen2.5-1.5B-Instruct fine-tuned with QLoRA, in Ollama: mendwright lists at most 40 elements of the step's role from the captured page (`mendwright.candidates`), the model answers which one the step meant or that none fits (removed, ambiguous, or moved to another page), and mendwright builds the XPath for the pick itself, never from its position, and checks it like any proposal. A pick the model is less than 80% sure of is declined (`MENDWRIGHT_LOCAL_MIN_CONFIDENCE` or `min_confidence=` changes that). When the checks refuse a pick because it is hidden or not unique on the live page, the model is asked once more without it; after any other refusal it doesn't guess again. `MENDWRIGHT_LOCAL_MODEL=<name>` or `MENDWRIGHT_PROVIDER=local` selects it, after cloud keys and the gateway and before `OLLAMA_MODEL`, and `mendwright doctor` shows it. On 3,000 held-out synthetic redesigns it picked the right element for 97.1% of broken selectors and a wrong one for 0.14%, and declined 97.1% of the steps whose element was gone; on the benchmark, behind the fingerprint tier, it healed 31 of 35 with no wrong heal. `training/` has the generator, the training and export scripts and the full results ([training/README.md](https://github.com/saadbuilt/mendwright/blob/main/training/README.md)).
- A provider that sets `wants_fingerprint = True` gets the key's saved fingerprint in the bundle, redacted like the expected text. Only `LocalModelProvider` does; hosted providers and gateways never get it.
- `benchmarks/run.py --provider local [--model NAME]`. For this provider the prompt size column counts the candidate task it sends.
- `mendwright model install` downloads the model file (about 1 GB, once) from this release's GitHub assets, checks it against a SHA-256 pinned in the code, writes an Ollama Modelfile next to it and runs `ollama create mendwright-selector`. `--dir`, `--name`, `--skip-create` and `--force` change where, what and whether. The Modelfile template now lives in `mendwright.model_install`, which `training/export.py` also uses.
- `OpenAICompatibleProvider.for_ollama()` and an `OLLAMA_HOST` set to `localhost` now reach Ollama on 127.0.0.1. On Windows a request to `localhost` tried IPv6 first and waited about 2 seconds per call before reaching Ollama on IPv4.

## [0.4.0] - 2026-10-12

- Heals without a model (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#heals-without-a-model)). Each time a key's selector matches, mendwright saves a fingerprint of the element: its tag, the attributes that survive redesigns, its text or label, and its ancestors, never an input's value. When the selector breaks, mendwright scores the page's elements against it first, and heals with no model call when one element scores at least 0.40, no other comes within 0.12, it shares an id, test id, name, link, label or text with the recorded element (the same numbers and words, allowing a typo, a plural or a filler word), and it sits inside the recorded containers that are still on the page. The pick goes through the same checks as a model's. With no provider configured, these heals still happen. It is on by default; `mendwright.open(fingerprint=False)`, `MENDWRIGHT_FINGERPRINT=0` or `MENDWRIGHT_DISABLE=1` turns it off. On the benchmark it healed 20 of 35 broken selectors with no wrong heal, with thresholds tuned on those same cases.
- No changes per step (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#no-changes-per-step)): `page = mendwright.open(page).page` on Playwright, sync or async, and `driver = mendwright.open(driver).driver` on Selenium. `page.locator(selector)`, the page shortcuts that take a selector, and `find_element()` with `By.XPATH`, `By.CSS_SELECTOR`, `By.ID` or `By.NAME` go through `heal.locator()`, with the selector as the key. Reads, `set_input_files`, `focus` and `find_element()` keep Playwright's and Selenium's own answer for a hidden element or several matches, and heal only a selector that matches nothing. Everything else goes to the real object, and `.native` is that object. A `find_element()` that can't find or heal the element raises an `AttentionRequired` that is also Selenium's `NoSuchElementException`.
- `heal.locator(..., intent="the terms checkbox in the signup form")` describes an element in words (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#describing-an-element-with-intent)). It is saved with the key, redacted, and given to the model on one line of the prompt (the reference gateway builds the same line). With `role=` and no selector, a model finds the element on first use, and the saved XPath is used from then on.
- `mendwright fix` writes confirmed heals back into your code (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#mendwright-fix)). It prints a diff of the string literals it would change, and `--apply` writes them, checking that each Python file still parses and changed only in the planned strings. It leaves alone keys marked destructive, heals inside an iframe, unconfirmed heals (unless `--include-unconfirmed`), keys whose old selector is a bare word, a key in `heal.locator(key, ...)` and `role=` or `text=` values, and a selector passed where only CSS runs, such as `By.CSS_SELECTOR`, and lists each with the reason.
- `mendwright report --format html` writes one self-contained page (no scripts, nothing loaded from the network) with the keys, recent heals, flow events and quarantines, and `--out FILE` writes any format to a file.
- `mendwright doctor` says whether the fingerprint tier is on, and `--json` has a `fingerprint` entry.
- `HealEvent` has a `source`: `"fingerprint"`, `"model"` or `"intent"`. The journal's `heal.proposed`, `heal.rejected` and `heal.applied` carry the same `source`, and a fingerprint heal has `"provider": "fingerprint"`.
- Drivers can have an optional `fingerprint(selector, frame_chain=())`, which the built-in Playwright and Selenium drivers have.
- The benchmark runs the fingerprint tier first, as `mendwright.open()` does. `--no-fingerprint` measures the provider alone, and the results show which tier made each heal.
- Flow changes (see the [guide](https://github.com/saadbuilt/mendwright/blob/main/docs/guide.md#flow-changes)):
  - `heal.interrupt(key, selector, action="click", args=(), role=None)` registers a step that can show up at any point, such as a cookie banner, a newsletter modal or an "are you still there?" dialog. mendwright handles it when it is in the way of a step (the step's element is missing, the page shows it before an action, or an action fails because something covered the element), then goes on with the step. A failed action is retried once, and only after an interruption was handled, never when Playwright's call log says the action was already done. At most 3 are handled per step. An interruption is never healed, and a later `heal.locator()` for its key is skipped when the element isn't there. When an action fails because its element was covered or couldn't be reached and no interruption matched, one WARNING names the ones mendwright looked for, since one whose selector no longer matches is the likeliest cause.
  - `mendwright.open(page, cookies="reject")` or `cookies="accept"` registers an interruption for the consent banners of OneTrust, Cookiebot, Didomi, TrustArc, Usercentrics, Quantcast Choice, Osano, cookieconsent, CookieYes and Complianz, with a fallback for other banners. The fallback acts only inside a short element that mentions cookies and holds no text field or navigation, so a consent screen that isn't about cookies (an OAuth Allow, a terms step) or a button such as Close account is never clicked. It is off by default.
  - `heal.locator(..., optional=True)` skips a step whose element isn't there instead of healing it. Proxies have `.present`, which is False for a skipped step, and its actions do nothing.
  - The prompt tells the model it may answer `{"xpath": null, "reason": "..."}` when no element on the page fits the step, and not to pick an element that is only similar. Providers report that as "the model says no element on this page fits: <reason>", and the reference gateway passes it on. The prompt also names the page path and the path where the key was last found.
  - All of this works the same in `mendwright.aio`, where actions awaited together look for interruptions one at a time.
  - New journal events: `flow.interrupt`, `flow.skip` and `flow.page_guard`.
- `mendwright demo` shows a cookie banner that now opens first and covers the form, handled as a registered interruption. `StandInPage` takes a `url=` and knows an overlay that blocks clicks until it is closed.
- An accuracy benchmark in `benchmarks/`: 47 cases where a redesign breaks a selector (12 of them where the right answer is no heal, 4 of those a step that moved to another page), a harness that runs them through `mendwright.open()` with any provider or a model-free baseline, and the baseline results. It is not part of the package. See [docs/benchmark.md](https://github.com/saadbuilt/mendwright/blob/main/docs/benchmark.md).

### Changed

- `heal.page` on a Playwright healer is now a stand-in for the page (`HealingPage`, or `AsyncHealingPage` in `mendwright.aio`), and `heal.driver` on a Selenium healer is a stand-in for the WebDriver (`HealingDriver`). They pass `isinstance()` checks, and `.native` is the real page or driver. `heal.driver` on Playwright and `heal.page` on Selenium are as before.
- With no provider configured, a broken selector heals when its fingerprint finds the element with confidence. The `mendwright.open()` warning, `mendwright doctor` and the pytest header say so.
- `overrides.json` now stores a `fingerprint` for every key whose selector matched while the tier is on, not only for healed keys, and an `intent` when you pass one. The file is written when a fingerprint changes. [SECURITY.md](https://github.com/saadbuilt/mendwright/blob/main/SECURITY.md) lists what a fingerprint holds.
- A fingerprint heal doesn't count toward the hourly rate limit, and isn't reported to the provider's `report_outcome()`.
- A key is no longer healed on a page other than the last few its element was found on. The store saves those pages (`lastPage` and `pages` in `overrides.json`, at most 5; numbers, uuids and other generated ids in a path count as one page), and such a heal is declined before any model call with an error that says the flow looks changed. Pass `heal_across_pages=True` to `mendwright.open()` to heal there anyway, for example after a redesign that only changed the URL. Pages loaded with `page.set_content()` (`about:blank`) are never compared.

## [0.3.0] - 2026-10-11

First public release. Earlier versions were developed privately as selfheal and never published.

- Drivers for Playwright (sync and async, including patchright and camoufox) and Selenium, behind one `mendwright.open(page)`. `heal.locator(key, selector)` takes XPath, CSS or Playwright selectors. A heal is always an XPath.
- Providers for Anthropic, OpenAI and compatible APIs, Gemini, Bedrock, LiteLLM, Ollama and your own gateway. `auto_provider()` picks one from the environment, and there is no default model. `ANTHROPIC_BASE_URL` and `OPENAI_BASE_URL` are honoured for proxies and compatible hosts.
- Local checks before a heal is used: not an index-only path, not quarantined or superseded for the key, one match in the captured HTML, the step's role, and one visible match on the live page that still has the role. A heal whose action fails is quarantined, and the quarantine blocks the same element, not just the same selector string.
- Keys you mark as destructive are never healed and never sent to a model: `destructive=True` in `heal.locator()`, `mendwright.open(destructive_keys=...)`, or `"destructive": true` in a seed file. mendwright doesn't guess this from the key or the page.
- Page capture removes scripts, styles, comments and head metadata, and redacts values, URLs and long numbers, including in broken selectors and expected text. Direct providers have an hourly rate limit and an optional spend cap.
- A pytest plugin: the `heal` fixture, an overridable `mendwright_provider` fixture, and `--mendwright-strict`, which also fails reruns from pytest-rerunfailures. Heals from a passing test are confirmed.
- The `mendwright` command: `demo` (offline, or `--live` with the model from your environment), `doctor` and `report`.
- Heals are saved in `.mendwright/overrides.json`, with a journal next to it. A corrupt store raises instead of being overwritten. Each applied heal prints one line to stderr.
- Python 3.10 to 3.14, with lxml as the only dependency.

### Changed
