# Benchmark results

How often does a heal land on the right element, and how often does mendwright accept a wrong one? [docs/benchmark.md](../docs/benchmark.md) explains the cases, the grading and the caveats. This page is generated by `python benchmarks/report.py` from the files in `benchmarks/results/`.

The corpus has 47 cases: 35 where a heal is the right answer and 12 where the right answer is to not heal.

## Model runs

Each model row is one run on one date. Results vary between runs and model versions, so compare rows from the same date where you can.

To add a model run (the key and endpoint come from your environment, as in `mendwright doctor`):

```bash
python benchmarks/run.py --provider anthropic --model <model id>
python benchmarks/run.py --provider openai --model <model id>
python benchmarks/run.py --provider gemini --model <model id>
python benchmarks/run.py --provider ollama --model <model name>
python benchmarks/run.py --provider local --model mendwright-selector
python benchmarks/report.py
```

Each of these runs the fingerprint tier first, as mendwright.open() does. Add --no-fingerprint
to measure the model alone.

"Wrong" counts heals that landed on another element in a case where a heal was right. "Wrong on negatives" counts heals in cases where the right answer was to not heal. Both are heals mendwright accepted, after its checks, onto an element the step did not mean.

The fingerprint tier is part of mendwright and on by default: while the old selector still matches, mendwright records the element, and when it breaks, mendwright looks for that element on the new page before it asks any provider. It heals only when one element matches with confidence, and its pick goes through the same checks as a model's. A row marked + fingerprint ran the tier before the provider; the fingerprint tier alone row has no provider behind it. Use --no-fingerprint for a run without it.

The fingerprint tier's numbers are in-sample. Its thresholds (a score of 0.40, a margin of 0.12 over the next element, and a shared id, test id, name, link, label or text) were tuned on these same 47 cases until it made no wrong heal here. That shows the tier can be set to make no wrong heal on this corpus, not that it makes none on your pages. Pages written to probe it after the tuning did find wrong heals (a row button for another row, a button whose text changed one word, a Save button in another form), and the rules were tightened until it declined them; those pages are tests in tests/test_fingerprint.py, not cases here, so they are not counted above. Its pick goes through the same checks as a model's, and those checks cannot tell a plausible wrong element from the right one.

The similarity baseline records the element while the old selector still matches, and later picks the most similar element on the new page. A model gets less: the key, the old selector and the new page, never the old page.

## get_by calls

The call corpus has 19 cases: 11 where a heal is the right answer and 8 where the right answer is to not heal.

The same redesigns, with the step written as a `heal.page.get_by_*()` call instead of `heal.locator(key, selector)`: a call that found the step's element on the old page and finds nothing on the new one, such as `get_by_role("link", name="Sign in")` once the link reads "Log in". Each call case in `benchmarks/calls/` takes its pages from a case of `benchmarks/cases/` and its truth too. They run in a real browser only (`--calls --browser chromium`), since only Playwright runs a call.

A heal_get_by=True row is 0.10.0's behaviour: the fingerprint only, no model. A heal_get_by='model' row asks the model when the fingerprint does not heal the call. A cold row skips the old page, so each call never matched before the redesign: there is no fingerprint and no page the key was found on, so the page guard cannot stop a step that moved, and mendwright asks the model only for a `get_by_role()` call (any other call names no kind of element its pick could be checked against). "Saved with a twin" counts heals saved with a get_by twin, a call that matched the healed element and nothing else when the heal was made; "twin finds the right element" checks that call on the new page against the case's truth.

There are few call cases, so one case moves a rate by 9 points (positives) or 12 points (negatives). The calls were written for these pages after the pages existed, and the fingerprint tier and the local model were not tuned on them, but the local model was trained on pages like the ones in `benchmarks/cases/`.
