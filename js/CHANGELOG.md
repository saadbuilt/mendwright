# Changelog

All notable changes to the npm package `mendwright` are documented here. The Python package has [its own changelog](https://github.com/saadbuilt/mendwright/blob/main/CHANGELOG.md).

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and version numbers follow [Semantic Versioning](https://semver.org/spec/v2.0.0.html).
While the version starts with 0, a minor release can change the public API.

## [0.2.0] - Unreleased

### Added

- `open(page, { dismiss: true })`, and `mendwrightOptions: { dismiss: true }` for the fixtures, dismiss a popup nobody registered when it covers the element of an action, with the Python package's rules: Escape (only while the focus is on the page's body or in the popup, outside an iframe, and never with `cookies: 'accept'`), then the popup's close button, then a decline button such as No thanks. A button that accepts, subscribes, pays or goes somewhere, a priced one, a link with a real href, a bare ×, a label, a form's submit or reset button, a control that holds a field, a disabled one and a toggle are never clicked, an alert dialog is left alone, a popup that asks (a Cancel or Keep button) gets Escape only, and a consent banner is left alone with `cookies: 'accept'`. Each dismissal logs one WARNING, writes a `flow.dismiss` journal event and is listed in `heal.handledInterruptions` under `'<popup>'` (`DISMISS_KEY`). A popup that comes back each time throws `InterruptionLoop` after 3, with a `flow.stop` event whose code is `popup_loop`. The page scripts are the Python package's, character for character, and the tests compare the rules, the texts and the journal line with the Python package's.
- With `dismiss: true`, the locators `heal.page` doesn't heal (`getBy*`, a locator built with options, chained locators, `frameLocator()`, `and()`, `or()`, `first()`, `last()`, `nth()`, `filter()` and those of `heal.page.locator(selector).all()`) get the interruption and popup checks before their actions. They aren't healed, nothing about them is saved, and `expect()` takes them.
- `heal.locator(key, selector, { expectValue })` and `open(page, { expectValues: { key: check } })`, and `mendwrightOptions: { expectValues }` for the fixtures, check what a read returns when the element was found through a selector a heal saved, in this run or an earlier one, as the Python package's `expect_value=` does. A check is `'money'`, `'number'`, `'integer'`, `'percent'`, `'date'`, `'email'` or `'url'`, a `RegExp` (a search, whose `g` and `y` flags are left out) or a function. The reads are `innerText()`, `textContent()`, `inputValue()` and `getAttribute()` of `heal.locator()`, `heal.page` and `heal.page.locator()`. A value that passes is returned and confirms a heal made in this run. One that fails quarantines the heal, is logged as a WARNING, and the read throws `AttentionRequired` instead of returning it; the journal gets a `heal.canary` (`by: 'expect_value'`) for a heal made in this run and a `heal.quarantine`, whose `reason`, such as `expect_value: innerText() is not money`, never holds the value. A read through the selector in your code is never checked, and `null` passes no check. A check that can never work throws `TypeError` at once. The checks are the Python package's, and the tests compare them with it on a table of over 450 values and on the character classes they rest on, for every character Python knows.
- `parseMoney()` and `parseNumber()` read an amount as the checks do, and give it as the string Python's `Decimal` prints, such as `'1299.00'`, or `null`.
- `heal.interrupt(key, selector, { run })` answers an interruption that needs a form, such as a session-expired sign-in or a postcode prompt, with an async function of yours, as the Python package's `run=` does. It gets `heal.page`, so its own selectors heal, and mendwright calls it at the same moments as any interruption, awaits it and waits for the element to go away. Its own actions never handle its own interruption, so it is never called from inside itself, but they handle the others, such as a cookie banner over its form. No popup is dismissed while it runs, and another step of the same healer, such as one awaited next to it in `Promise.all()`, waits for it and never calls it a second time. A handled one logs `handled interruption 'session_expired' before 'search' with relogin()` and writes a `flow.interrupt` event with `action: 'run'` and `function`, and one still there after 3 throws `InterruptionLoop`, whose message names the function. What it throws is thrown as it is, after one WARNING and a `flow.interrupt` event with `outcome: 'failed'` and the error's name; an `AttentionRequired` from it is never taken for a miss of the step, so nothing is healed or skipped. A function that returns something that isn't a promise throws `TypeError` when it is handled, and `run` with `action` or `args`, a `run` that isn't a function and `heal.interrupt(key, null, { run })` throw `TypeError` at once. A function without a name of its own is called `<anonymous>`. The tests compare the texts and the journal lines with the Python package's, and run its `mendwright notify` on them. The types `InterruptOptions` and `RunFunction` are exported.
- `heal.step(name, { when, url, last, optional }, fn)` and `heal.runSteps({ timeoutMs, pollMs })` run a flow whose steps the site shows in another order, on one page, or not at all, as the Python package's `heal.step()` and `run_steps()` do. `when` is a landmark, a selector or a list, and `url` a pattern for the page's path with the Python package's `fnmatch` rules; a landmark is looked up with the browser's count and visibility only, never healed, and nothing is saved for it. `runSteps()` waits for a step that hasn't run to show, awaits its function, which gets `heal.page`, and looks again, until the step with `last: true` ran, or, with no last step, every step that isn't optional. Each step runs once; steps that show together run in the order registered, and the last step only when no other shows. While it waits, the registered interruptions are handled, up to 3 in each wait, as `'<next step>'` (`WAITING_STEP`), and one whose action failed is not tried again in that wait. It throws `AttentionRequired` after a `flow.stop` event when a step that ran is on the page again (`step_again`), shows on another page (`step_moved`), when no step shows (`no_step`, naming the page and every landmark) and after 3 times as many runs as steps (`step_cap`), and `TypeError` for a function that returns no promise. Each step logs one INFO line and writes a `flow.step` event with the Python package's fields; a step that runs before one registered ahead of it logs one WARNING, and so does a step that never showed once the last step ran. While a step runs, a key found during it before heals on the page the step showed on, whatever its address, with one INFO line; the store saves the steps each key was found during as `steps` (`SelectorStore.setLastStep()`), only for a key found on the page its step showed on, and once the step's function went to another page, the page guard is as before. The step lives in the async context of its function, so a lookup awaited next to `runSteps()`, a callback the function left behind and a run function of `heal.interrupt()` aren't part of it. Arguments that can never work throw `TypeError` or `InvalidSelector` at once. The tests compare the url patterns, the landmarks' targets, the messages, the argument checks and the journal lines with the Python package's, run its `mendwright notify` on the events, and check that each package heals a key in its step's new place from the `steps` the other saved. The types `StepOptions`, `StepFunction` and `RunStepsOptions` are exported.
- Iframes one level down, as the Python package handles them on Playwright. A key whose own selector matches nothing on the page but one element inside one iframe of the page is followed there, with no model call: the selector is saved with its `xpath=` or `css=` prefix written out and the iframe's selector as `frameXPath`, built from the iframe's id, name or title, or from its `src` up to the query (a generated-looking id or name is skipped, and the bare tag is never used), once the page guard and the live check in the iframe pass. It logs `found 'terms' inside the iframe ...`, writes a `heal.applied` with `provider` and `source` `frame` and the iframe's selector in `frame`, and is a heal with source `frame` in `heal.heals`, which its canary checks and `mendwrightStrict` fails on, and which is never reported to the provider. It isn't followed in dry run, under `MENDWRIGHT_DISABLE=1`, while a guard blocks heals, for a key marked destructive, a match in several iframes or several elements, an iframe inside another iframe, an iframe nothing tells apart, a Playwright engine selector, a lookup quarantined or superseded before, on a page the key was never found on, or for an element that fails the live check: the `AttentionRequired` says why and how to open mendwright on that frame, such as `open(page.frame({ name: 'consent' }))`, and the journal gets a `heal.declined` with the code `frame` (`dry_run` and `disabled` in those modes). The tests compare the rules, the iframe's selector and the texts with the Python package's, and check that each package looks up and heals the key in the iframe the other saved.
- A key whose own XPath matches nothing on the page or in an iframe but one element inside one open shadow root is followed there, as the Python package does on Playwright, with no model call: through a CSS form of that element, saved as the chain of the hosts and the CSS with the hosts as `shadowHosts`, once the page guard and the live check inside the shadow root pass. It logs `found 'save' inside the shadow root of ...`, writes a `heal.applied` with `provider` and `source` `shadow` and the hosts in `shadow`, and is a heal with source `shadow` in `heal.heals`, which its canary checks and `mendwrightStrict` fails on, and which is never reported to the provider. Only a key mendwright has no record of, or one last found in that same shadow root, is followed, and never one of whose selectors matches something on the page; a CSS selector isn't, since Playwright's CSS reaches into open shadow roots by itself. It isn't followed in dry run, under `MENDWRIGHT_DISABLE=1`, while a guard blocks heals, for a key marked destructive, a match in several shadow roots or several elements, a host nothing tells apart, an element no CSS selector tells apart, a lookup quarantined or superseded before, a page with more than 200 open shadow roots or 2,000,000 characters of their HTML, on a page the key was never found on, or for an element that fails the live check: the `AttentionRequired` says why, and the journal gets a `heal.declined` with the code `shadow` (`dry_run` and `disabled` in those modes). The tests compare the rules, the texts and the journal line with the Python package's, run its `mendwright notify` on the events, and check that each package looks up the key in the shadow root the other followed it into.
- `heal.locatorAll(key, selector, { role, timeoutMs, pollMs, optional, nonempty })` gives the elements of a list, a `HealLocator` for each in page order, as the Python package's `heal.locator_all()` does. Each time a selector of the key matches two or more elements, it records the list fingerprint, saved as the Python package saves it, and each package reads the other's. mendwright never uses a list that your own selectors don't match: when none matches and the key has a list fingerprint, the lookup waits `timeoutMs`, handling interruptions, and throws `AttentionRequired` with the Python package's text, since an emptied list can't be told from a selector that broke, asks no model and saves nothing (a `heal.declined` with the code `list_empty`). Without a list fingerprint, with `optional: true` and while the fingerprint tier is off, it gives `[]` at once. The elements' actions handle interruptions and popups as `heal.locator()`'s do and confirm or quarantine nothing, and their reads aren't checked against `expectValues`. `nonempty` other than `true` or `false`, and `nonempty: true` with `optional: true`, throw `TypeError` at once. `LocatorAllOptions` is exported.
- `open(page, { healGetBy: true })`, `MENDWRIGHT_HEAL_GET_BY=1` and `mendwrightOptions: { healGetBy: true }` for the fixtures look up and heal `getByRole()`, `getByText()`, `getByLabel()`, `getByPlaceholder()`, `getByAltText()`, `getByTitle()` and `getByTestId()` on `heal.page`, as the Python package's `heal_get_by=True` does. A call is saved under a key written as the Python package writes it, such as `get_by_role("button", name="Sign in")`, so one store serves both packages, and `getByKey()` builds one for `destructiveKeys`, `expectValues` and `heal.present()`, which also read the call written in another spelling, such as `get_by_role('button', name='Pay')`. A call that matches nothing for `timeoutMs` is healed from the fingerprint mendwright recorded when it last matched, never by a model, even one configured, and a heal of a `getByRole()` call must also have the call's ARIA role, and its `level`, by Playwright's own matcher on the live page. A call that matches several elements or one hidden element, or that the browser rejects, goes to Playwright as written, and no saved heal answers it. A miss throws `GetByNotFound`, which is Playwright's `errors.TimeoutError` and an `AttentionRequired` too. The registered interruptions are handled before the wait and logged before the call's key. `isVisible()`, `count()`, `waitFor()`, `all()` and `expect()` answer for the call as written, and a call chained from a locator, `first()`, `nth()`, `filter()`, `and()`, `or()`, `frameLocator().getBy*()` and `heal.page.native.getBy*()` stay unhealed. A call that matches only inside an iframe throws, saying mendwright doesn't follow it there, and one whose element is inside an open shadow root heals only inside it. A call with a state option, `includeHidden: true`, an empty role, name or text, an option this version doesn't read, a `RegExp` with flags other than `i`, `m` and `s`, or a `RegExp` whose source the Python package's `re` module can't read back the same way, is never a key: it goes to Playwright as written, with one INFO line. Off, `heal.page.getBy*` are as before. A heal that isn't made is a `heal.declined` with the Python package's code `get_by`. The tests compare the keys, the reading of other spellings, the regular expressions, the texts and the journal lines with the Python package's, and check that each package heals a call from the fingerprint the other recorded. `GetByNotFound`, `getByKey()`, `getBySetting()` and the type `GetByMethod` are exported.
- With `nonempty: true`, a list none of whose selectors matches is looked for on the captured page with the Python package's search, its refusals and their texts: another list, under another heading or in another part of the page, placeholders, a word for a state the list didn't have, and the live check. What it finds is never used: it is saved as a proposed list heal with the Python package's evidence and id, which the Python package's `mendwright lists` shows and `mendwright lists accept` accepts, the journal gets a `heal.held`, and the lookup throws `AttentionRequired` with the commands to check it, accept it and write it into your code. After you accept it, the lookup still throws until the selector is in your code (code `list_waits_fix`). When the selector a list heal replaced matches again, a proposed one is no longer proposed and an accepted one is quarantined, with a WARNING and a `heal.quarantine`. No model is asked about a list. The tests compare the search with the Python package's on its 86 pages of emptied lists and redesigns, and run its command line on what this package saved.
- The README's "The command line" says how a team that writes its tests in TypeScript runs the Python package's `mendwright report`, `fix`, `lists`, `notify` and `check`, and its GitHub Action, on this package's store, such as `pipx run mendwright fix --apply --glob "*.ts"`. A test runs `mendwright fix` on a TypeScript test with heals this package confirmed: it writes them into the file's strings, leaves comments and `getBy*` calls alone, and the file still parses.

### Changed

- A key last found inside an open shadow root heals inside it, as the Python package's does, where it was refused: mendwright enters it strictly through its saved hosts, the fingerprint tier and the model read only that shadow root's HTML and interactive elements, and the XPath they find is checked there and saved as a CSS selector for the same element, built from a test id, an id, other attributes or class names, once that CSS passed the live check inside the shadow root. It logs `healed 'save' inside the shadow root of ...`, and its `heal.applied` has the hosts in `shadow`. A shadow root that can't be entered now (a host gone, matching several elements or with a closed shadow root), one inside an iframe, a host nothing tells apart and an element only its text tells apart are refused with the Python package's reasons, and the key is never looked for on the page around the host instead. A quarantine counts in its own place: one made inside a shadow root blocks its element there under any CSS form, and says nothing about the page, and the other way round. The tests compare the CSS forms, on every element of a table of pages, the texts, the store rows and the journal line with the Python package's, and check that each package runs and heals again the key the other healed inside a shadow root.
- A key last found inside an iframe heals inside that iframe, as the Python package's does, where it was refused: the fingerprint tier scores the iframe's elements, a model gets the iframe's HTML and elements, and both halves of the gate check the iframe's document, so an element that looks the same on the page around it is never picked. The heal is saved with the same `frameXPath` and its `xpath=` prefix written out, so it never shares a store row with the same XPath on the page, and only a quarantine made in that iframe blocks it. When that iframe is no longer on the page, the key heals on the page, as in the Python package. A key last found inside a shadow root in an iframe is still refused, with the code `shadow`.
- The fingerprint's score and the selector of an iframe read an id as generated when a part of it mixes letters with a digit that Python's `str.isdigit()` counts, such as ², as the Python package reads it.
- The entries of `heal.handledInterruptions` have `popup`, `how` and `label`, which are `null` for a registered interruption, as the Python package's `InterruptionEvent` has them.
- The registered interruptions an action or a read handles are handled under the healer's lock, as a lookup's are and as on the Python package's async healer, so two steps awaited together never handle one at once.
- A string is read as a `getBy*` call written out, such as `get_by_role("button", name="Go")`, by a reader of Python's call syntax that runs nothing, as the Python package reads one, where a pattern took any text of that shape. So `heal.locator()`, `heal.locatorAll()` and `heal.interrupt()` refuse as a key just the strings the Python package refuses, with its message, and they and `heal.step({ when })` refuse one as a selector, with a message that names `open(page, { healGetBy: true })`. A stored candidate written as a call, as the Python package's seed files can hold, runs as that call.
- The store keeps the `getBy` field the Python package saves with a heal of a `get_by_*` call since its 0.11.0 (a suggested call for `mendwright fix`) when it writes `overrides.json`, and takes in one another process saved, as it does `css`. This package never runs it.
- The store keeps any field of a candidate or of a key's entry in `overrides.json` that this package doesn't know, as the file has it, where a write of this package dropped it, so a field a later version of either package saves stays. It reads only `overrides.json` in its folder, so the per-key records the Python package 0.11 keeps in `keys/` next to it are left alone.
- A store URL in `storePath`, `mendwrightStore` or `MENDWRIGHT_STORE`, such as the `s3://` and `https://` stores the Python package 0.11 reads, throws `TypeError` that names the option and the scheme and quotes nothing of the URL, where it was taken for a local path. This package keeps its store in a local file.

## [0.1.0] - 2026-11-01

The first release: the Python package's `heal.locator()` and `heal.page` for Playwright Test.

- `import { test, expect } from 'mendwright/test'` makes the `page` fixture heal: `page.locator(selector)` and the page methods that take a selector heal when the selector broke, with the selector as the key. The `heal` fixture is the healer, and the heals of a test are confirmed when it passes. `mendwrightStrict` fails a test that passed only because of a heal. `mendwright/test` has its types under every TypeScript `moduleResolution`, `node10` (the default with `"module": "commonjs"`) included.
- `open(page)` and `heal.locator(key, selector, { role, destructive, optional, intent })` for a page you opened yourself.
- The fingerprint tier, with the Python package's scoring, thresholds and text rules, before any model call.
- Anthropic, OpenAI and compatible hosts, and Ollama (any model, or mendwright's own selector model) as providers, picked from the same environment variables as the Python package. A base URL with a user name or password in it (`baseUrl`, `ANTHROPIC_BASE_URL`, `OPENAI_BASE_URL`, `OLLAMA_HOST`) is refused when the provider is built, with an error that names only its scheme and host, and a provider's error text masks the user info of any URL in it.
- The gate: an XPath is used only when it isn't an index-only path, isn't quarantined or superseded and doesn't reach a quarantined element, and matches exactly one element of the key's role in the captured page and one visible element of that role on the live page.
- Keys marked destructive, keys on a page they were never found on, keys whose role is unknown and steps while a guard blocks are never healed. A heal whose action fails in the browser is quarantined. A key last found inside an iframe or a shadow root is refused after the checks for a key marked destructive and the page guard, and that refusal has the code `dry_run` or `disabled` in those modes, as the Python package's has, so `mendwright notify` doesn't count it as needing a human.
- Open shadow roots: the fingerprint read saves where the element is as the key's `shadowHosts`, as the Python package 0.10.0 does, and a key last found inside a shadow root is never healed, so a look-alike on the page around its host is never picked. A heal the Python package saved inside a shadow root runs strictly there: each host must match one element and have an open shadow root, and only a match inside it counts, at the lookup and again right before each action and read of the `HealLocator`, which waits for that up to the step's timeout and throws `AttentionRequired` when the page changed after the lookup and it never comes; when the Locator matches nothing at all, as after a Close button's click removed its dialog, `isVisible()` and `isHidden()` answer `false` and `true` at once, as Playwright's do. The fingerprint reads a form field's `<label for=...>` in the field's own shadow root, as the Python package does.
- Pages that enforce Trusted Types: mendwright parses the captured page through a Trusted Types policy of its own, named `mendwright`, made once for each document, so the gate, the cleaning and the local model's candidates work there. A page whose `trusted-types` directive doesn't allow that policy gets no heal, and the model is sent nothing. A page that can't be cleaned of its scripts and styles is never sent to a model.
- `cookies: 'reject'` and `cookies: 'accept'`, and `heal.interrupt()`.
- The store is the Python package's `.mendwright/overrides.json` (schema 2) with its lock file and merge, and the journal is its `journal.jsonl`, so one store can be shared by both packages. A leading `~` in `MENDWRIGHT_STORE`, `mendwrightStore` and `storePath` is the home directory, for the fixtures as for `open()` and the Python package. Each journal line has the run id the Python package 0.10.0 gives it (`MENDWRIGHT_RUN_ID`, or `gh-<run id>.<attempt>` on GitHub Actions), and a heal that did not apply is a `heal.declined` with its code (for a key last found inside a shadow root or an iframe, `dry_run` and `disabled` in dry run and under `MENDWRIGHT_DISABLE=1`, as the Python package gives them), the `heal.quarantine` of a heal saved before its key was marked destructive has `by` `destructive`, and an interruption that kept coming back a `flow.stop`, so the Python package's `mendwright notify` sums up a run of this package too. It keeps the `shadowHosts` the Python package 0.10.0 saves for a key and a heal inside an open shadow root, merges them as it merges `frameXPath`, and, as the Python package does, drops a heal's `shadowHosts` when your code passes that heal's chain, and reads them back from the heal's chain when the Python package 0.9.0 dropped them in a write of its own, so a key whose heal the Python package saved inside a shadow root is still never healed on the page around its host.
